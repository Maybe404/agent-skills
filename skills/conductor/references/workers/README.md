# Worker 适配器

每个 worker 用一份适配器文档描述怎么驱动它。流程里的派发、拿结果、续接、权限等动作，都按所选 worker 的适配器执行。角色和怎么选 worker 见 SKILL.md。

|---|---|---|
| 宿主 subagent | 宿主内部 | 见当前宿主的扩展（[../hosts/](../hosts/README.md)） |

## 适配器契约

每份适配器文档都要回答下面这些问题。缺了哪一项，流程里对应的步骤就没法做，用之前先补上。

1. **预检**：怎么确认它此刻能用（凭据、额度、模型名）。
2. **派发**：非交互地启动一个任务的命令；怎么传 brief（文件、stdin、附件）；怎么指定工作目录。
3. **拿结果**：最终回复在哪里（stdout、输出文件、事件流里的哪个字段）。
4. **成败判断**：失败时的退出码和错误信息在哪里。
5. **续接**：会话 ID 从哪里来；怎么带着上下文继续同一个会话（返工要用）。
6. **权限映射**：只读 / 工作区可写 / 全权限三档，分别对应什么参数；有没有真正的沙箱。
7. **选模型**：怎么指定模型和推理强度；怎么列出可用模型。
8. **审查模式**（可选）：有没有专门的审查命令，怎么限定审查范围（全量、只审某个提交）。
9. **写评论**：在各权限档位下，worker 能不能自己调用 `scripts/conductor comment`；能的话署名怎么传（通常是环境变量 `CONDUCTOR_AUTHOR`）。
10. **已知的坑**：实测踩过的问题和绕法。

## 用户选的 worker 没有适配器时

1. 请用户提供调用方式：命令名、非交互模式的参数、文档链接，或者一条用户自己跑通过的命令。
2. 你自己查 `--help` 和文档，按 [_template.md](_template.md) 起草一份适配器，契约里每一项都要有答案；查不到的标"未知"。
3. 用很小的任务实测：预检、派发、拿结果、失败时的退出码、续接，各跑一遍。实测过的标"已验证"，没跑的标"未验证"。
4. 把草稿给用户看，用户同意后存进本目录（`<name>.md`），并加进上面的表格。
5. 实测不通的项目，在流程里绕开它，并告诉用户这会影响哪一步（例如不能续接，就意味着返工只能新开会话加汇总）。
